# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Typst Editor: real-time collaborative Typst editor. Svelte 5 SPA (`frontend/`), Go `net/http` JSON + WebSocket API (`backend/`), MariaDB (`database/`). Features: multi-user editing via OT (CodeMirror 6 + `@codemirror/collab`), live SVG preview compiled in the browser (typst.ts WebAssembly, incremental; falls back to the server) and PDF viewer produced by the system `typst` binary, manual GitHub pull/push via the system `git` binary, project sharing (owner invites registered users as members), JWT auth and admin user management. All user-facing text, error messages, log lines and code comments are in **Spanish** — keep it that way.

## Commands

Backend (run from `backend/` — config loads `.env` from the current directory):
```bash
go run .                         # start API + built frontend on :8080 (same as `go run . serve`)
go run . key:generate            # write a new JWT_SECRET into .env
go build -o bin/server .         # build binary (bin/ is gitignored)
go vet ./...
go test ./...                    # unit tests (collab changesets) + git push/pull integration test
go test ./internal/collab -run TestApplyChangeSet
```

Frontend (from `frontend/`):
```bash
npm run dev       # Vite on :5173, proxies /api (incl. WebSocket, ws: true) -> http://localhost:8080
API_TARGET=http://127.0.0.1:18080 npm run dev   # proxy (dev and preview) to another backend
npm run build
```

Production build (from the repo root): `./build.sh [--skip-install]` runs `npm ci` + `vite build` + `go build` and leaves `./typst-editor` (binary) and `./public/` (frontend) at the root; both are gitignored, as is `/data/`. Run `./typst-editor` from the root with a `.env` there.

Database bootstrap (once): `sudo mariadb < database/01_setup.sql`. Runtime needs `typst` and `git` on PATH (or `TYPST_BIN`/`GIT_BIN`); project data lives in `DATA_DIR` (default `backend/data/`, gitignored). No frontend tests or linters are configured.

## Architecture

### Backend
- `main.go` sits at the `backend/` root (no `cmd/` dir) and dispatches subcommands. Module path `typsteditor/backend`; packages under `internal/`.
- `internal/config` — the DSN forces `loc=UTC` and session `time_zone='+00:00'` so TIMESTAMPs serialize correctly regardless of the DB server's zone; keep both if you touch the DSN. Hand-rolled `.env` loader (doesn't override real env vars). Startup fails if `JWT_SECRET` < 32 chars.
- `internal/database` — `Migrate` runs the `schema` statements (`users`, `github_accounts`, `projects`, `project_members`, `project_folders`, `project_user_prefs`) with `CREATE TABLE IF NOT EXISTS`, then idempotent MariaDB `ALTER TABLE … IF [NOT] EXISTS` statements that migrate older installs, and seeds the first admin. **Schema is duplicated** in `database.go` and `database/01_setup.sql`; change both. No migration framework: schema changes to existing tables are appended to `schema` as idempotent `ALTER … IF NOT EXISTS` (MariaDB-specific syntax).
- **Project access**: every project endpoint goes through `loadProject`, which uses `projectSelect` + `projectAccess` to allow only owner, `project_members` row, or admin role, and returns 404 otherwise. The query also yields `access` (`owner|member|admin`), `members` count and the current user's `starred`/`folder_id` (from `project_user_prefs`). It also returns `member_names` (GROUP_CONCAT); `listProjects` adds `editors` from `hub.ActiveEditors` (live WS presence, excluding the caller). Every `?` in `projectSelect` is the current user ID — always build args with `selectArgs(u, extra...)`. `projectOrder` puts starred projects first (most recently starred on top), then by `updated_at`.
- **Templates & cloning** (`templates.go`): `projects.is_template` (+ category/description) publishes a project to every user. `projectForCopy` widens `loadProject` with `OR p.is_template = 1` and marks such read-only rows `access: "template"`; only `listTemplates`, `cloneProject` and `thumbnail` may use it — every editing endpoint must keep using `loadProject`. Cloning flushes the hub under the source's `projectLock`, copies the working tree (no `.git`, hidden files or symlinks) and `git init`s a fresh repo. `projectTemplate()` is the default new-project content (us-letter, `es`/`mx`).
- **Personal organization** (`folders.go`): folders (with a `color` key from a fixed palette mirrored in `Projects.svelte` `FOLDER_COLORS`) and stars are per user and never affect other members; `updatePrefs` upserts `project_user_prefs` (keeps `starred_at` when re-starring) and only accepts the caller's own folders. Removing a member deletes their prefs row. Settings/delete/invite need `canManage` (owner or admin). New project endpoints must call `loadProject` rather than querying `projects` directly. Removing a member calls `hub.KickUser`, which sends `closed` with `revoked: true` and drops their sockets.
- `internal/httpapi` — `server.go`: routes (Go 1.22+ `"METHOD /path"` patterns), middleware, JSON helpers; `handlers.go`: auth/users; `projects.go`: projects, files, compile, git; `members.go`: members and user search; `ws.go`: collaboration WebSocket. `requireAuth` re-reads the user from the DB on every request (`currentUser(r)`). The WS endpoint can't use headers, so it authenticates with `?token=` itself and is registered outside `requireAuth`. `browser.go`: resources for the in-browser compiler (`/api/typst/fonts`, `/fonts/meta`, `/fonts/{id}`, `/api/typst/packages/{ns}/{name}/{version}` — the server's local/cached packages tarred on the fly, else downloaded once from packages.typst.org into `DATA_DIR/packages` —, `/preview/files` + `/preview/file?path&v` serving the preview mirror). `export.go`: project `.zip` download (working tree without `.git`/hidden/symlinks, streamed, images stored uncompressed); since a browser download can't send `Authorization`, the client first gets a single-use, 1-minute ticket from `POST /export/ticket` and navigates to `GET /export.zip?ticket=` (registered outside `requireAuth`; re-checks user and `loadProject`). The «Exportar» section of `ShareModal.svelte` uses it, and downloads the PDF through the existing `/pdf` endpoint. `static.go` serves the built frontend from `STATIC_DIR` (when empty, `config.defaultStaticDir` picks `public/` next to the executable, else `../frontend/dist`) on the `/` catch-all: real files are served (hashed `assets/` cached as immutable and gzipped in memory on first request (the 28 MB compiler `.wasm` goes out as ~11 MB), no hidden files or directory listings), anything else falls back to `index.html` (`no-cache`); unknown `/api/` paths get a JSON 404 instead. If `index.html` is missing it logs a warning and serves only the API. Bodies capped at 1 MiB except `/upload` (20 MB). Long handlers (compile, git) extend the 15 s server write timeout with `longRequest`. Errors are `{"error": "<mensaje>"}`.
- `internal/collab` — the OT authority. `Hub` holds open `Doc`s keyed by `projectID:path`; text is `[]uint16` because CodeMirror positions are UTF-16 code units (`changeset.go` applies `ChangeSet.toJSON()` and builds diff changesets). A push is accepted only if its base version equals the current version; otherwise the client rebases (client-side, via `receiveUpdates`) and retries — the server never transforms. Bounded history (`maxHistory`) lets reconnecting clients resume with `since=`. Docs are saved to disk with debounce and unloaded when the last peer leaves (saved under the hub lock to avoid a stale reload race). **Disk can lag memory**: anything that reads project files (compile, git, raw download) must call `hub.FlushProject` first. External content changes to an open file (git pull, upload) must go through `hub.ReplaceText` so clients receive them as a normal update; deleted files go through `hub.CloseDoc`. `hub.BumpRev` increments a per-project revision and broadcasts `rev` (text edits also carry `path`, so the browser preview only re-downloads files it isn't editing) — it's the cache key for compiled preview/PDF and the client's recompile trigger.
- `internal/typst` — runs `typst compile --root <dir> --diagnostic-format short` (through `nice -n 10` when available, at most `NumCPU/2` processes server-wide), outputs to `DATA_DIR/build/<id>/` (outside the repo so it's never committed); parses diagnostics. **Preview and thumbnail compile against a mirror**, not the project: `mirror.go` keeps `build/<id>/preview/` as real dirs + symlinks to the originals, the main file copied (typst canonicalizes the input, so a symlink would fall outside `--root`), and PNG/JPEG over 1.6 Mpx replaced by downscaled copies (`proxy.go`). Copies keep typst's natural size exactly (it takes DPI from EXIF X/YResolution ignoring the unit → JFIF → pHYs → 72, plus EXIF orientation; copies carry an EXIF block with the exact DPI as a rational), so pagination matches the PDF, which still uses the originals; when metadata is doubtful no copy is made. `build/<id>/preview.json` records size+mtime per image so copies are only regenerated when the original changes. Never write through mirror entries (they're symlinks into the project): use `writeAtomic`. **Preview ↔ source sync** (`sync.go`): the CLI exposes no source spans, so `typst eval` (on the mirror, same pagination) queries par/heading/figure/list/enum/terms/table/raw blocks for page, y and plain text, and `matchBlocks` finds each text in the `.typ` files by word trigrams. `loadSources` orders the files as the document visits them (DFS over literal `#include`s from main, unreached files last); among several occurrences the one matching the most consecutive words wins, ties go to the first one after the previous block in that order. Block-level precision; generated text is skipped. Served by `/preview/sync`, cached per rev under its own mutex. **Extra font dirs**: `config.FontDirs` = repo `fonts/` (free fonts only, versioned: Roboto, Roboto Mono; found next to the executable or at `../fonts`) + `DATA_DIR/fonts` (local/licensed fonts, e.g. Calibri, never committed) + `FONT_PATHS`; `main.go` puts them in `TYPST_FONT_PATHS`, which every typst child process inherits. `Fonts()` and the compile cache (`cacheFor` clears `s.cache` when `FontsSignature()` changes) notice added/removed files without a restart. **Fonts for the browser** (`fonts.go`, `fontmeta.go`): `Fonts()` builds, once per font-dir signature, the catalog typst itself sees — paths from `typst fonts --variants` (strip the ` (Variable)` suffix) plus the fonts embedded in the typst binary, extracted by scanning it for sfnt headers (so they always match the installed version; embedded go last, as typst loads them) — each identified by its SHA-256. `Meta()` sends a gzipped bundle of *skeletons* (only head/hhea/maxp/name/OS2/cmap/fvar/avar/STAT/MATH and `post` cut to a v3 header): the WASM `get_font_info` gives exactly the same FontInfo on them as on the full file (~3 MB for 454 fonts instead of 320 MB); the browser downloads a full font only when the document uses it. `PreviewFiles` syncs the mirror and lists its files with a size+mtime version. SVG pages are stored content-addressed in `build/<id>/pages/<hash>.svg`; `/preview` returns only `{hash, width, height}` per page and `PrunePages` keeps the current and previous compile's pages.
- `internal/imgopt` — lossless PNG/JPEG optimization (no external tools). PNG: picks the smallest of palette (≤256 colors, typical for diagrams), gray and truecolor at `BestCompression`, keeps `pHYs`/`eXIf`/`iCCP`/`sRGB`/`gAMA`/`cHRM` (so typst's natural size and colors don't change), drops text/time chunks, skips APNG, and **verifies the decoded pixels are identical** before accepting. JPEG: only strips COM/XMP/APP3–13/15 segments (never re-encodes). One image at a time (`slots`, ~1 GB peak for 65 Mpx). Used by `/upload` (`optimize=1`) and `POST /images/optimize {path}` (one file per request so the client shows progress; atomic write under `projectLock`). `/upload` also accepts `path` to replace an existing file.
- `internal/github` — minimal GitHub REST client (`/user`, `/user/repos`, branches); base URL from `GITHUB_API`. `httpapi/github.go` manages per-user `github_accounts` (token validated against `/user`, never returned) with a 2-minute in-memory repo-list cache. Projects reference an account via `github_account_id`; `projectSelect` joins it to get the token used by `s.remote(p)`. Only one's own accounts can be assigned (`ownAccount`), but a project keeps a foreign account when edited by an admin.
- `internal/gitsync` — shells out to git. HTTPS remotes only (`ValidateRemote`); token passed per call as `http.extraHeader`, never stored in `.git/config`; `core.symlinks=false` and disabled hooks so pulled content can't escape the project dir. Errors meant for users are `*gitsync.UserError` (`BranchMissing` marks an empty repo / missing branch: project creation then falls back to `git init` + template). Compile and git ops on a project are serialized by `Server.projectLock`.
- File paths from clients go through `cleanPath` (no traversal, no hidden/`.git` entries) and `regularFile` (Lstat, rejects symlinks).

### Frontend
- Hash routing in `App.svelte` (`#/`, `#/login`, `#/usuarios`, `#/p/<id>`); `Workspace.svelte` is lazy-loaded so CodeMirror stays out of the main bundle. Pages in `src/routes/`, shared code in `src/lib/`.
- `lib/editor/collab-client.js` — `CollabSession` owns one WebSocket + `EditorView` per open file: pushes `sendableUpdates` one batch at a time (`inflight` until `pushed`), applies `updates` with `receiveUpdates`, reconnects with backoff resuming from `getSyncedVersion`. Cursors are only sent when there are no pending local changes; received cursors are mapped through pending changes (`lib/editor/cursors.js`).
- `lib/editor/typst-lang.js` — hand-written `StreamLanguage` highlighter (markup/code/math mode stack); no Lezer grammar.
- `lib/workspace/FileTree.svelte` — file explorer built from the flat `files` list (paths): collapsible folders (collapsed set persisted per project in `localStorage` `typsteditor.tree.<id>`, ancestors of `currentPath` auto-expand), accent/case-insensitive search over the full path (Enter opens the first match, Esc clears), icons by extension.
- **In-browser compilation** (`lib/preview/`): `typst.worker.js` runs typst.ts (`@myriaddreamin/typst-ts-web-compiler` + `-renderer`, **pinned to 0.8.0-rc4 = typst 0.15**; `WASM_TYPST` must match the server's typst minor version or the preview falls back to the server, since pagination must match the PDF). Fonts are lazy (`add_lazy_font` + sync XHR, FontInfo computed from the skeletons and cached in IndexedDB by catalog etag); project files come from the preview mirror via `map_shadow` (the open file via `add_source` with live editor text); packages through `set_package_registry` + an in-memory access model under `/@memory/packages`. Compiles with `incr_compile` (~0.25 s per edit on the 248-page thesis, ~6 s cold, ~1.5 GB worker memory) and keeps the first full artifact + deltas; warnings come from a cached `snapshot().compile(0, 3)` because `incr_compile` omits them. The renderer omits what a session already emitted (it is built to patch a DOM), so every render batch uses a fresh session (base + merged deltas), and `svgpage.js` cuts `render_in_window` output into standalone per-page SVGs (only the defs each page references, no `<foreignObject>` text layer). `engine.js` wraps the worker in promises.
- `lib/workspace/Preview.svelte` — compiles in the browser by default (`livePath`/`liveVersion`/`liveText` from the open `CollabSession`, `onDocChange`; `remoteKey` bumps on `rev` for other files → re-sync files); page keys are `<doc>:<index>` and a rendered page whose SVG signature didn't change keeps its blob URL. While the worker prepares, one server compile is shown, and the first browser compile waits for it (two >1 GB compiles at once would swap on a small box). Any worker failure → `fallback()` to the server path below. Server path, virtualized: reserves each page's box (aspect ratio from `/preview`), downloads pages near the viewport (IntersectionObserver, 4 in parallel, blob URLs keyed by hash, LRU of 24) and mounts an `<img>` only after the page stays close for 150 ms (each mounted SVG costs Chrome several MB until GC, so fast scrolling must not decode every page). Unchanged hashes are reused across recompiles; a changed page keeps showing the old version until the new one arrives. Clicking a page calls `onjump` (Workspace reuses `onDiagnostic`); clicking in the editor (`CollabSession` `onCursorClick`) calls the exported `reveal(file, line)`, which scrolls and briefly highlights the block. The sync map is fetched on first use and then refreshed 2.5 s after each compile. Zoom 40–400 % with Ctrl+wheel (non-passive listener added manually: Svelte's `onwheel` is passive), +/−/0 when focused, and the toolbar; `setZoom` keeps the page point under the pointer fixed. Left-drag pans (grab cursor); a drag sets `moved` so the following click doesn't jump to source. Compiles only while `active` (output panel visible), recompiling on `refreshKey` changes driven by WS `rev` messages with a debounce that grows with compile time. `PdfView.svelte` fetches the PDF blob into an iframe.
- `routes/Projects.svelte` — full-width page (rendered outside the `max-w-6xl` container in `App.svelte`); sticky sidebar on `lg`, scrollable chip row below it; grid/list layout and sort persisted in `localStorage`; polls the list every 30 s for live editors. Sidebar views (all/starred/own/shared/admin, folders, no folder), client-side search, optimistic star/move with rollback, HTML5 drag-and-drop onto sidebar folders. Cards use a stretched link (`after:absolute`) so the star/menu buttons can sit inside without nesting buttons in `<a>`.
- `lib/Thumb.svelte` — first-page PNG thumbnail with a module-level blob-URL cache (`invalidateThumb`). The Projects page has a `templates` view (gallery with category chips), clone/template modals and a "Desde plantilla" tab in the create modal.
- `lib/RepoPicker.svelte` — account select + searchable repo list + branch input (datalist), reused by the create-project modal and project settings. `routes/GitHubAccounts.svelte` manages accounts (`#/github`).
- **Editor toolbar**: `lib/editor/EditorToolbar.svelte` (reusable, CodeMirror-agnostic: icons only, tooltip with label · shortcut · Typst syntax after 400 ms, `active` state, heading and reference menus, tools fold into «Más» by width priority, roving tabindex) + `lib/editor/commands.js` (toggle `*`/`_`/`` ` `` marks and `#underline[…]`, headings, `-`/`+` lists, math/link/ref, table/figure templates, `activeFormats`, `formatKeymap` registered with `Prec.high` in `CollabSession`; `onState` reports the cursor state once per frame). Image insertion goes through `lib/workspace/ImageModal.svelte` (pick from the project with `FolderPicker pick="file"` + preview, or hand off to `UploadModal.openInsertImage`). `lib/editor/imageHover.js` is a CodeMirror `hoverTooltip` over `image("…")` showing a thumbnail (`lib/workspace/imageCache.js`) and «Cambiar…»/«Subir nueva»; replacing rewrites only the string literal (tracked `from`/`to`, `insertMedia` with `ctx.replace`). Paths in code are resolved relative to the open file (`resolvePath`).
- **Bibliografía** (`lib/bib/`): `bibtex.js` parses BibTeX/BibLaTeX keeping UTF-16 positions of type, key and every field value, and its edit helpers (`setField`, `removeField`, `setKey`, `setType`, `deleteEntry`, `appendEntry`) return **minimal changes** (only the touched value), so the rest of the file keeps its formatting and git diffs stay small; new fields go before trailing metadata (`META`: `creationdate`…). `BibEditor.svelte` is the visual mode of a `.bib` (Workspace toggle «Visual | Código», persisted in `localStorage` `typsteditor.bibmode`): it edits the **same** `CollabSession` document through `applyChanges` (`userEvent: 'input.visual'`, so remote users get normal OT updates and Ctrl+Z works), re-parses on every `liveVersion`, follows the selected entry with `session.track(entry.from)` (key as fallback) and never overwrites a field that is focused or has a pending debounced write. New/imported/duplicated entries get `creationdate` (JabRef's field; ignored by typst). Import: pasted BibTeX or a DOI (`fetchDoi`: doi.org content negotiation, then Crossref, from the browser). «Añadidas recientemente» (`library.js` `byRecent`) = `creationdate`/`date-added`/`timestamp`, else the first time this browser saw the key (`localStorage` `typsteditor.bibseen.<id>`; keys present on the first visit count as old), ties → lower in the file is newer. `CiteModal.svelte` (toolbar «cite», Ctrl+Alt+C, ref menu) lists entries of every `.bib` (closed files via `api.textFile`, cached until a WS `rev` for that path: `invalidateText`), multi-select, `#cite` form and supplement (`citeCode`: `@key[…]` when the key allows it, else `#cite(label("…"))`), and warns when the `.bib` isn't in any `#bibliography(…)` (offers to append it when the open file is the main file). `complete.js` adds an `@` completion source (bib keys by recency + `<labels>`) through `EditorState.languageData`. `.bib` files get `lib/editor/bib-lang.js` highlighting.
- `lib/FolderPicker.svelte` — reusable JetBrains-style folder chooser: editable path field (own text state so «media/» can be typed), toolbar (new folder inline — Esc stops propagation so the containing `Modal` stays open —, expand/collapse all), hierarchical tree with a root node, keyboard (arrows, Home/End, F2/Insert). Props: `folders` (ancestors are filled in), `bind:value` ('' = root), `pick="file"` + `files` (also lists files; value is the chosen file, `onpick` on double-click/Enter), `rootLabel`, `allowCreate`, `disabled`, `height`, `oncreate`. New folders live only in the picker until something is saved there (git has no empty dirs). `Modal` accepts `wide="xl"`. `lib/Drawer.svelte` is the right-side variant (full height, fixed header and optional `footer` snippet, scrolling body; same Esc/focus-trap behavior) used for project settings — a submit button in the footer targets the body's form with `form="<id>"`.
- `lib/workspace/UploadModal.svelte` — Uppy (core, dashboard inline inside our `Modal`, xhr-upload with the Bearer header and `dir`/`optimize`/`path` meta, no drop-target plugin); modes `openUpload(dir)` / `openReplace(path)` (FileTree «Reemplazar» on non-editable files) and `addFiles(files, {folder, autostart})`. Drops on `FileTree` resolve the target from the nearest `[data-dir]` (folder `li`, a file's parent, or the root `ul`), highlight it, auto-expand collapsed folders after 700 ms and upload immediately; drops on the editor are intercepted by a CodeMirror `domEventHandlers.drop` (`CollabSession` `onFilesDrop`, otherwise CM would insert the file's text) and open the modal asking for the folder (`suggestFolder`). The drop position is tracked (`CollabSession.track`, mapped through every change). After upload, images are inserted by `Workspace.insertMedia`: always `#image("…", width: 80%)` with a path relative to the open file (`lib/editor/snippets.js`); if the user typed a caption for that file in the modal (per-file inputs), it is wrapped in `#figure(…, caption: […]) <fig-…>` (caption escaped with `escapeContent`, unique label). Editor drops insert at the drop point (checked by default); uploads from the button or the explorer can opt in and insert at the cursor of the open `.typ` (`editingFile`). `insertBlock` puts the block after the paragraph containing the position, separated by blank lines. `Workspace` prevents the browser from opening files dropped elsewhere. Lazy-loaded by `Workspace.svelte` (`{#await import(...)}`) because Uppy is ~250 KB. `OptimizeModal.svelte` optimizes existing images one request at a time with progress.
- `lib/session.svelte.js` — global session (`$state`), token in `localStorage` (`typsteditor.token`). `lib/api.js` — `request()`/`requestBlob()` wrappers; any 401 clears the session; `wsURL()` builds the editor socket URL.
- **Themes** (light/dark/solarized): `lib/theme.svelte.js` sets `<html data-theme>` (persisted in `localStorage` `typsteditor.theme`; an inline script in `index.html` applies it before paint); switcher in `Navbar.svelte`. Themes in `app.css` redefine Tailwind's palette variables (`--color-slate-*`, state tints, `--color-primary*`) plus `--color-surface`, `--color-nav`, `--editor-*` and `--syn-*` (CodeMirror theme and `typst-lang.js` highlight use `var(...)`). Use `bg-surface` for panel/card backgrounds, never `bg-white` (`text-white` sits on colored backgrounds and must stay white); preview pages stay `bg-white` (paper). Inline colors should mix with theme vars (see folder colors in `Projects.svelte`).
- Page transitions stack views in one grid cell (`[grid-area:1/1]`). Tailwind CSS 4; design tokens and component classes (`btn-primary`, `btn-secondary`, `btn-sm`, `input`, `label`, `card`, `badge`, `alert-error`, `alert-info`) are in `src/app.css` — reuse them.
