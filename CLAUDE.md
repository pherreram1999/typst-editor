# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Typst Extend: real-time collaborative Typst editor. Svelte 5 SPA (`frontend/`), Go `net/http` JSON + WebSocket API (`backend/`), MariaDB (`database/`) or libSQL/Bunny Database (`DB_DRIVER`). Features: multi-user editing via OT (CodeMirror 6 + `@codemirror/collab`), an MCP server for AI agents (OAuth 2.1 or personal tokens), live SVG preview compiled in the browser (typst.ts WebAssembly, incremental; falls back to the server) and PDF viewer produced by the system `typst` binary, manual GitHub pull/push via the system `git` binary, project sharing (owner invites registered users as members), JWT auth and admin user management. All user-facing text, error messages, log lines and code comments are in **Spanish** — keep it that way.

## Commands

Backend (run from `backend/` — config loads `.env` from the current directory):
```bash
go run .                         # start API + built frontend on :8080 (same as `go run . serve`)
go run . key:generate            # write a new JWT_SECRET into .env
go build -o bin/server .         # build binary (bin/ is gitignored)
go vet ./...
go test ./...                    # unit tests (collab changesets) + git push/pull integration test
go test ./internal/collab -run TestApplyChangeSet
```

Frontend (from `frontend/`):
```bash
npm run dev       # Vite on :5173, proxies /api (incl. WebSocket, ws: true) -> http://localhost:8080
API_TARGET=http://127.0.0.1:18080 npm run dev   # proxy (dev and preview) to another backend
npm run build
```

Production build (from the repo root): `./build.sh [--skip-install]` runs `npm ci` + `vite build` + `go build` and leaves `./typst-editor` (binary) and `./public/` (frontend) at the root; both are gitignored, as is `/data/`. Run `./typst-editor` from the root with a `.env` there.

Database bootstrap (once): `sudo mariadb < database/01_setup.sql`. Runtime needs `typst` and `git` on PATH (or `TYPST_BIN`/`GIT_BIN`); project data lives in `DATA_DIR` (default `backend/data/`, gitignored). No frontend tests or linters are configured.

## Architecture

### Backend
- `main.go` sits at the `backend/` root (no `cmd/` dir) and dispatches subcommands. Module path `typsteditor/backend`; packages under `internal/`.
- `internal/config` — `DB_DRIVER` (`mysql`|`libsql`, `DBURL`/`DBAuthToken`; an `?authToken=` in the URL is moved to the token because the driver rejects it). The MariaDB DSN forces `loc=UTC` and session `time_zone='+00:00'` so TIMESTAMPs serialize correctly regardless of the DB server's zone; keep both if you touch the DSN. Hand-rolled `.env` loader (doesn't override real env vars). Startup fails if `JWT_SECRET` < 32 chars.
- `internal/database` — **two engines, chosen by `DB_DRIVER`**: `mysql` (MariaDB, `go-sql-driver/mysql`) or `libsql` (Bunny Database/Turso/sqld via `libsql-client-go`, pure Go, remote only; `DB_URL` + `DB_AUTH_TOKEN`, falling back to `BUNNY_DATABASE_URL`/`BUNNY_DATABASE_AUTH_TOKEN`). `Open` returns `*sql.DB` + a `Dialect` (`dialect.go`), passed to `httpapi.New` (`s.dialect`) and `oauth.Store.D`. Queries stay plain SQL that both engines accept (`CASE WHEN`, not `IF()`; times as `?` params from Go, not `UTC_TIMESTAMP()`); only non-portable fragments come from the dialect: `InsertIgnore`, `OnConflict(keys…)` + `Excluded(col)` (upserts), `GroupConcat`, `ForUpdate`, `IsDuplicate(err)` (never check `mysql.MySQLError` in handlers). `projectSelect` is built per dialect (`Server.projectSelect`). libSQL specifics (`libsql.go`): a connector wrapper sends `time.Time` args as UTC `2006-01-02 15:04:05` (same as `CURRENT_TIMESTAMP`, so string comparisons work) and re-runs `PRAGMA foreign_keys = ON` per stream when the server doesn't enable it by default (the driver closes the HTTP stream in `ResetSession`). Columns declared `TIMESTAMP` come back as `time.Time`, but expressions (`MAX(…)`) come back as text: scan them into `database.NullTime`. `Open` with `mysql` creates `DB_NAME` (utf8mb4) when it doesn't exist (error 1049; needs `CREATE`); a libSQL database must already exist (created in the provider's panel). `Migrate` runs `Dialect.Schema()` (+ `migrateLibSQL` on libSQL), then seeds the first admin; `serve` and the `migrate` subcommand (migrate only, then exit) both go through `openDB` in `main.go`. **Schema is in three places**: `schema_mysql.go` (`CREATE TABLE IF NOT EXISTS` + idempotent MariaDB `ALTER TABLE … IF [NOT] EXISTS` for older installs), `database/01_setup.sql` (MariaDB only) and `schema_libsql.go` (SQLite types, `CHECK` for enums, `COLLATE NOCASE` username, `updated_at` triggers standing in for `ON UPDATE CURRENT_TIMESTAMP`); change all three. No migration framework; SQLite has no `ADD COLUMN IF NOT EXISTS`, so a libSQL migration of an existing table must check `pragma_table_info` first. Integration test: `TYPSTEDITOR_LIBSQL_URL=http://127.0.0.1:18081 go test ./internal/database` against a throwaway `ghcr.io/tursodatabase/libsql-server` container.
- **Project access**: every project endpoint goes through `loadProject`, which uses `projectSelect` + `projectAccess` to allow only owner, `project_members` row, or admin role, and returns 404 otherwise. The query also yields `access` (`owner|member|admin`), `members` count and the current user's `starred`/`folder_id` (from `project_user_prefs`). It also returns `member_names` (GROUP_CONCAT); `listProjects` adds `editors` from `hub.ActiveEditors` (live WS presence, excluding the caller). Every `?` in `projectSelect` is the current user ID — always build args with `selectArgs(u, extra...)`. `projectOrder` puts starred projects first (most recently starred on top), then by `updated_at`.
- **Templates & cloning** (`templates.go`): `projects.is_template` (+ category/description) publishes a project to every user. `projectForCopy` widens `loadProject` with `OR p.is_template = 1` and marks such read-only rows `access: "template"`; only `listTemplates`, `cloneProject` and `thumbnail` may use it — every editing endpoint must keep using `loadProject`. Cloning flushes the hub under the source's `projectLock`, copies the working tree (no `.git`, hidden files or symlinks) and `git init`s a fresh repo. `projectTemplate()` is the default new-project content (us-letter, `es`/`mx`).
- **Import from the computer** (`import.go`): `POST /api/projects/import`, streamed multipart (own body limit, exempt in `limitBody`): `name` first, then either `archive` (a .zip, spooled to a temp file next to `DATA_DIR/projects` — not `/tmp`, which may be tmpfs) or repeated `path` + `file` pairs (Go's multipart drops directories from filenames, so paths go in their own field). Hidden entries/`.git`/`__MACOSX` are skipped, other paths go through `cleanPath`; a single common top folder in a zip is stripped; non-UTF-8 zip names are decoded as CP437. Limits: 512 MB body, 100 MB per file, 1 GB uncompressed, 10 000 files. `pickMainFile`: root `main.typ`, else a root `.typ` nobody `#include`s, else the shallowest; no `.typ` → 400. Fresh `git init`, no remote; any failure deletes the row and dir. Frontend: «Desde mi equipo» tab of the create modal in `Projects.svelte` with `lib/ImportPicker.svelte` (.zip, folder via `webkitdirectory`, or drag-and-drop of a zip/folder/files; skips hidden files client-side so a `.git` is never uploaded); `api.importProject` uses XHR for upload progress.
- **Personal organization** (`folders.go`): folders (with a `color` key from a fixed palette mirrored in `Projects.svelte` `FOLDER_COLORS`) and stars are per user and never affect other members; `updatePrefs` upserts `project_user_prefs` (keeps `starred_at` when re-starring) and only accepts the caller's own folders. Removing a member deletes their prefs row. Settings/delete/invite need `canManage` (owner or admin). New project endpoints must call `loadProject` rather than querying `projects` directly. Removing a member calls `hub.KickUser`, which sends `closed` with `revoked: true` and drops their sockets.
- `internal/httpapi` — `server.go`: routes (Go 1.22+ `"METHOD /path"` patterns), middleware, JSON helpers; `handlers.go`: auth/users; `projects.go`: projects, files, compile, git; `members.go`: members and user search; `ws.go`: collaboration WebSocket. `requireAuth` re-reads the user from the DB on every request (`currentUser(r)`). The WS endpoint can't use headers, so it authenticates with `?token=` itself and is registered outside `requireAuth`. `browser.go`: resources for the in-browser compiler (`/api/typst/fonts`, `/fonts/meta`, `/fonts/{id}`, `/api/typst/packages/{ns}/{name}/{version}` — the server's local/cached packages tarred on the fly, else downloaded once from packages.typst.org into `DATA_DIR/packages` —, `/preview/files` + `/preview/file?path&v` serving the preview mirror). `export.go`: project `.zip` download (working tree without `.git`/hidden/symlinks, streamed, images stored uncompressed); since a browser download can't send `Authorization`, the client first gets a single-use, 1-minute ticket from `POST /export/ticket` and navigates to `GET /export.zip?ticket=` (registered outside `requireAuth`; re-checks user and `loadProject`). The «Exportar» section of `ShareModal.svelte` uses it, and downloads the PDF through the existing `/pdf` endpoint. `static.go` serves the built frontend from `STATIC_DIR` (when empty, `config.defaultStaticDir` picks `public/` next to the executable, else `../frontend/dist`) on the `/` catch-all: real files are served (hashed `assets/` cached as immutable and gzipped in memory on first request (the 28 MB compiler `.wasm` goes out as ~11 MB), no hidden files or directory listings), anything else falls back to `index.html` (`no-cache`); unknown `/api/` paths get a JSON 404 instead. If `index.html` is missing it logs a warning and serves only the API. Bodies capped at 1 MiB except `/upload` (20 MB). Long handlers (compile, git) extend the 15 s server write timeout with `longRequest`. Errors are `{"error": "<mensaje>"}`.
- `internal/collab` — the OT authority. `Hub` holds open `Doc`s keyed by `projectID:path`; text is `[]uint16` because CodeMirror positions are UTF-16 code units (`changeset.go` applies `ChangeSet.toJSON()` and builds diff changesets). A push is accepted only if its base version equals the current version; otherwise the client rebases (client-side, via `receiveUpdates`) and retries — the server never transforms. Bounded history (`maxHistory`) lets reconnecting clients resume with `since=`. Docs are saved to disk with debounce and unloaded when the last peer leaves (saved under the hub lock to avoid a stale reload race). **Disk can lag memory**: anything that reads project files (compile, git, raw download) must call `hub.FlushProject` first. External content changes to an open file (git pull, upload) must go through `hub.ReplaceText` so clients receive them as a normal update; deleted files go through `hub.CloseDoc`. `hub.BumpRev` increments a per-project revision and broadcasts `rev` (text edits also carry `path`, so the browser preview only re-downloads files it isn't editing) — it's the cache key for compiled preview/PDF and the client's recompile trigger.
- `internal/typst` — runs `typst compile --root <dir> --diagnostic-format short` (through `nice -n 10` when available, at most `NumCPU/2` processes server-wide), outputs to `DATA_DIR/build/<id>/` (outside the repo so it's never committed); parses diagnostics. **Preview and thumbnail compile against a mirror**, not the project: `mirror.go` keeps `build/<id>/preview/` as real dirs + symlinks to the originals, the main file copied (typst canonicalizes the input, so a symlink would fall outside `--root`), and PNG/JPEG over 1.6 Mpx replaced by downscaled copies (`proxy.go`). Copies keep typst's natural size exactly (it takes DPI from EXIF X/YResolution ignoring the unit → JFIF → pHYs → 72, plus EXIF orientation; copies carry an EXIF block with the exact DPI as a rational), so pagination matches the PDF, which still uses the originals; when metadata is doubtful no copy is made. `build/<id>/preview.json` records size+mtime per image so copies are only regenerated when the original changes. Never write through mirror entries (they're symlinks into the project): use `writeAtomic`. **Preview ↔ source sync** (`sync.go`): the CLI exposes no source spans, so `typst eval` (on the mirror, same pagination) queries par/heading/figure/list/enum/terms/table/raw blocks for page, y and plain text, and `matchBlocks` finds each text in the `.typ` files by word trigrams. `loadSources` orders the files as the document visits them (DFS over literal `#include`s from main, unreached files last); among several occurrences the one matching the most consecutive words wins, ties go to the first one after the previous block in that order. Block-level precision; generated text is skipped. Served by `/preview/sync`, cached per rev under its own mutex. **Extra font dirs**: `config.FontDirs` = repo `fonts/` (free fonts only, versioned: Roboto, Roboto Mono; found next to the executable or at `../fonts`) + `DATA_DIR/fonts` (local/licensed fonts, e.g. Calibri, never committed) + `FONT_PATHS`; `main.go` puts them in `TYPST_FONT_PATHS`, which every typst child process inherits. `Fonts()` and the compile cache (`cacheFor` clears `s.cache` when `FontsSignature()` changes) notice added/removed files without a restart. **Fonts for the browser** (`fonts.go`, `fontmeta.go`): `Fonts()` builds, once per font-dir signature, the catalog typst itself sees — paths from `typst fonts --variants` (strip the ` (Variable)` suffix) plus the fonts embedded in the typst binary, extracted by scanning it for sfnt headers (so they always match the installed version; embedded go last, as typst loads them) — each identified by its SHA-256. `Meta()` sends a gzipped bundle of *skeletons* (only head/hhea/maxp/name/OS2/cmap/fvar/avar/STAT/MATH and `post` cut to a v3 header): the WASM `get_font_info` gives exactly the same FontInfo on them as on the full file (~3 MB for 454 fonts instead of 320 MB); the browser downloads a full font only when the document uses it. `PreviewFiles` syncs the mirror and lists its files with a size+mtime version. SVG pages are stored content-addressed in `build/<id>/pages/<hash>.svg`; `/preview` returns only `{hash, width, height}` per page and `PrunePages` keeps the current and previous compile's pages.
- **Enlace de revisión** (`httpapi/review.go`, `typst/snapshot.go`): one saved compile per project, shared publicly by token (`project_reviews`: token 32 random bytes base64url, `allow_download`, `compiled_at/by`). Files live in `DATA_DIR/review/<id>/` (outside `build/`, removed with the project): `meta.json`, `document.pdf` (original images) and `pages/page-NNNN.svg` (rendered from the preview mirror, so downscaled images). `Compiler.Snapshot` writes to a temp dir and swaps it in, so a failed compile (422 with diagnostics) keeps the previous version. Managing (`GET/POST/PUT/DELETE /api/projects/{id}/review`) needs `canManage` except GET; «Actualizar» recompiles and keeps the token, `new_token` revokes the old link. Public routes outside `requireAuth`: `GET /api/review/{token}` (info + page sizes + `version`), `/pages/{n}?v=` (SVG, same CSP as preview pages), `/document.pdf` (403 when downloads are off: the PDF is never served then). Frontend: `lib/workspace/ReviewShare.svelte` (section in `ShareModal`), `routes/Review.svelte` at `#/r/<token>` rendered by `App.svelte` before the session guards (no login; `api.js` doesn't redirect to login from `#/r/`), pages mounted only near the viewport.
- **Enlaces de invitado** (`httpapi/invites.go`, `auth/guest.go`): URL firmadas `#/i/<id>.<exp>.<nonce>.<hmac>` (HMAC-SHA256 con una clave derivada de `JWT_SECRET`; la caducidad va dentro de lo firmado) que caducan en horas/días/meses (≤ 720 h, 365 días, 12 meses) y dan acceso sin cuenta, `edit` o `view`. Tabla `project_invites` (nonce, label, permission, expires_at, joins; revocar = borrar la fila; las caducadas hace > 30 días se purgan al listar). Gestión (`GET/POST /api/projects/{id}/invites`, `DELETE …/invites/{inviteId}`) con `canManage`; públicas `GET /api/invite/{token}` (vista previa) y `POST /api/invite/{token}/join {name}` → JWT de invitado (`IssueGuest`: audiencia propia y sujeto `guest:N`, que `Parse` nunca acepta), válido hasta la caducidad del enlace. `Server.authenticate` acepta ambos tokens y revalida el enlace en la BD en cada petición (y cada 30 s en el WebSocket). Un invitado es un `User` sintético (`Role: "guest"`, ID negativo aleatorio < 2^52) con `currentGuest(r)` en el contexto; **solo pasa por las rutas registradas con `shared(...)`** en `Routes` (proyecto, archivos, vista previa, fuentes/paquetes, PDF, WS); `authed(...)` le responde 403, así que una ruta nueva queda cerrada a invitados salvo que se registre con `shared`. `loadProject` usa `guestProject` (solo el proyecto del enlace, `access: "guest"`, `read_only`, sin datos de GitHub); las escrituras llaman a `requireWrite` y el WS cierra un `push` de solo lectura. Revocar expulsa con `hub.KickPeers` (`Peer.Invite`). Frontend: `routes/Invite.svelte` (vista previa con el nombre, aleatorio de `lib/guestName.js` o propio, guardado en `localStorage` `typsteditor.guestName`; la sesión vive en `sessionStorage` `typsteditor.guestSession` y en memoria con `enterGuest`/`leaveGuest`, sin tocar el token guardado; un 401 en modo invitado vuelve a la vista previa en vez de cerrar sesión), `lib/workspace/InviteLinks.svelte` (sección del diálogo Compartir), y en `Workspace` `guest`/`readOnly` ocultan ajustes, miembros, GitHub, .zip y, en solo lectura, la edición (`CollabSession readOnly`: `EditorState.readOnly` + `changeFilter` que bloquea todo cambio local; los remotos llegan con `filter: false`).
- **Correo y cuentas** (`internal/mail`, `httpapi/accounts.go`, `httpapi/emailinvites.go`): Resend (`github.com/resend/resend-go/v4`; `RESEND`/`RESEND_API_KEY`, `MAIL_FROM`); `mail.Sender` con `Enabled()`, plantillas HTML+texto en `templates.go` (todo el contenido variable escapado). Sin clave no se envía nada y las respuestas traen `link` (+ `mail_sent: false`, `mail_error`) para que la UI lo muestre y se copie (`mailResult`). Los enlaces son `PUBLIC_URL/#/<ruta>` (`appLink`). `users.email` (único, minúsculas, NULL en cuentas anteriores) y `password_hash = ''` = cuenta **pendiente** (`User.Pending`): no puede iniciar sesión (mismo 401 genérico). El login acepta usuario o correo. El admin crea cuentas solo con correo (usuario/nombre opcionales, `usernameFromEmail`) y se envía `#/cuenta/<token>` (`routes/Account.svelte`): `account_tokens` (purpose `setup` 7 d · `reset` 2 h · `email` 48 h; firma `auth.SignURLToken(PurposeAccount, …)`, un solo uso con `used_at`, se anulan los anteriores del mismo tipo). `POST /api/users/{id}/access-link` reenvía alta o restablecimiento; `POST /api/auth/forgot` responde 204 siempre (sin enumerar cuentas; 503 sin correo); `PUT /api/auth/me/email` envía un enlace y el correo se guarda al confirmarlo (nunca sin verificar, porque compartir con un correo registrado agrega directamente a esa cuenta); `lib/EmailPrompt.svelte` lo pide a las cuentas sin correo; `ADMIN_EMAIL` se asigna al admin inicial si no tiene. **Compartir por correo**: `addMember` acepta `{email}` (o un `username` con `@`): cuenta activa con ese correo → miembro + aviso `ProjectShared` (`addMemberUser`, async); si no, `project_email_invites` (una pendiente por proyecto+correo, 14 d, nonce renovado al reenviar) y `#/unirse/<token>` (`routes/Join.svelte`, `PurposeJoin`): `register` crea la cuenta con ese correo y la agrega; `accept` (con sesión) agrega al usuario actual; ambas de un solo uso (`claimJoin`). Pendientes en «Compartir» (reenviar/anular). `auth.SignURLToken(purpose, …)` usa una clave HMAC por propósito (`typsteditor/<purpose>/v1`), así un token de un tipo nunca vale para otro. **Sin correo** (`MAIL_ENABLED=false` o sin clave; `config.MailEnabled`): el alta sigue exigiendo correo, pero `sendAccessLink` → `setTempPassword` asigna una contraseña temporal (`tempPassword`, se devuelve una vez como `temp_password`) y `users.must_change_password = 1`; `requireSession` responde 403 `{code: "password_change_required"}` a todo salvo `allowedWithTempPassword` (`GET /api/auth/me`, `POST /api/auth/password`), y el WS y MCP también lo rechazan; `App.svelte` muestra el cambio obligatorio (`lib/ChangePassword.svelte`, también en el menú del nombre en `Navbar`). Definir la contraseña por enlace o con `POST /api/auth/password` pone el flag a 0. Migración: `schema_mysql.go` usa `ADD COLUMN IF NOT EXISTS`/`CREATE UNIQUE INDEX IF NOT EXISTS`; libSQL, `migrateLibSQL` (`libsqlColumns` comprobadas con `pragma_table_info`, luego `libsqlAfterColumns`) — añade ahí las columnas nuevas de tablas existentes.
- **MCP + OAuth** (`httpapi/mcp.go`, `mcp_tools.go`, `oauth.go`, `internal/oauth`): MCP server on `/mcp` with the official Go SDK (`github.com/modelcontextprotocol/go-sdk`, Streamable HTTP, `Stateless: true`), in-process because writes must go through the hub. Every tool is registered via `tool(...)`, which resolves the `mcpCaller` from `req.Extra.TokenInfo`. Each tool then calls `s.project(ctx, c, id, write)`, which checks four things: the user is re-read and must be active; access goes through `projectByID` with `mcpUser(u)` (role forced to `user`, so admins get no global access over MCP); the grant must include the project (`api_grant_projects`, where no rows means all projects); and `write` requires the `typst:write` scope. Never query `projects` directly in a tool. Text writes go through `s.editText` → **`hub.EditText`** (an open doc gets a server OT update plus a debounced save; a closed file gets an atomic write under the hub lock), never `os.WriteFile`. Binary writes go through `storeFile` (shared with `/upload`). `httpapi/core.go` `apiError`/`errf` lets the core helpers (`projectFiles`, `storeFile`, `removeFile`, `syncPoints`, `compilePDFLocked`, `cloneFrom`, `newBlankProject`) serve both HTTP handlers and tools. Download/upload links reuse `ticketStore` (`kind` file|pdf|zip|upload, bound to the grant, re-checked on use; served at `/api/mcp/files/{ticket}` and `PUT|POST /api/mcp/upload/{ticket}`). `upload_from_url` uses `fetchClient`, whose dialer `Control` rejects non-public IPs (SSRF). The authorization server is our own (the SDK has none): RFC 9728/8414 metadata, DCR (public clients, or confidential with a hashed secret), `/oauth/authorize` validates and then redirects to the SPA `#/oauth?…` (`routes/OAuthConsent.svelte`, uses the normal session, `POST /api/oauth/authorize`), PKCE S256 only, `resource` must be `PUBLIC_URL/mcp`, 1 h access tokens and 30-day rotating refresh tokens (reuse revokes the grant). Tokens are opaque (`tse_` personal, `tsa_` access, `tsr_` refresh) and stored only as SHA-256. Tables: `oauth_clients`, `oauth_codes`, `api_grants`, `api_tokens`, `api_grant_projects`. `config.PublicURL` (`PUBLIC_URL`) is the issuer. UI: `routes/McpAccess.svelte` (`#/mcp`, «Agentes») with `lib/GrantFields.svelte`. Login return path: `rememberReturn`/`takeReturn` in `api.js` (the App route guard navigates after login). E2E test: `TYPSTEDITOR_E2E_URL=… TYPSTEDITOR_E2E_ADMIN=user:pass go test ./internal/httpapi -run E2E` against a throwaway server and DB.
- `internal/imgopt` — lossless PNG/JPEG optimization (no external tools). PNG: picks the smallest of palette (≤256 colors, typical for diagrams), gray and truecolor at `BestCompression`, keeps `pHYs`/`eXIf`/`iCCP`/`sRGB`/`gAMA`/`cHRM` (so typst's natural size and colors don't change), drops text/time chunks, skips APNG, and **verifies the decoded pixels are identical** before accepting. JPEG: only strips COM/XMP/APP3–13/15 segments (never re-encodes). One image at a time (`slots`, ~1 GB peak for 65 Mpx). Used by `/upload` (`optimize=1`) and `POST /images/optimize {path}` (one file per request so the client shows progress; atomic write under `projectLock`). `/upload` also accepts `path` to replace an existing file.
- `internal/github` — minimal GitHub REST client (`/user`, `/user/repos`, branches); base URL from `GITHUB_API`. `httpapi/github.go` manages per-user `github_accounts` (token validated against `/user`, never returned) with a 2-minute in-memory repo-list cache. Projects reference an account via `github_account_id`; `projectSelect` joins it to get the token used by `s.remote(p)`. Only one's own accounts can be assigned (`ownAccount`), but a project keeps a foreign account when edited by an admin.
- `internal/gitsync` — shells out to git. HTTPS remotes only (`ValidateRemote`); token passed per call as `http.extraHeader`, never stored in `.git/config`; `core.symlinks=false` and disabled hooks so pulled content can't escape the project dir. Errors meant for users are `*gitsync.UserError` (`BranchMissing` marks an empty repo / missing branch: project creation then falls back to `git init` + template). Compile and git ops on a project are serialized by `Server.projectLock`. **Pull/push/status are owner-only** (`requireOwner`, not even admins: they use the project's GitHub credentials). **Pull conflicts** (`gitsync/merge.go`): `Pull` collects the three stages of every unmerged file (`ls-files -u`, blobs via `cat-file`; non-UTF-8, NUL or > 1 MiB → `binary`, pick a whole side), saves `MERGE_HEAD` in `refs/typsteditor/pull` and aborts, so the tree stays clean while the user resolves; the handler answers 409 `{error, conflict}`. `POST /git/pull/resolve {theirs, files: [{path, ours_blob, content | take: ours|theirs | delete}]}` commits new local edits, re-merges the saved commit with `--no-commit`, rejects if a conflict is new or a file's stage-2 blob differs from `ours_blob` (someone edited it meanwhile), writes the resolutions and commits; `reloadOpenDocs` pushes the result to open editors. Frontend: `lib/git/ConflictsDialog.svelte` (file list: accept yours / theirs / «Fusionar…») and `lib/git/MergeView.svelte` (JetBrains-style 3 panes: yours | editable result starting from base | theirs; » « × per change, wand applies non-conflicting changes, SVG bands between panes, synced scrolling by line mapping through the chunks, Alt+↑/↓). Chunk ranges in the result live in a `StateField` mapped in the same transaction (decorations must never see stale positions). `lib/git/diff3.js`: Myers line diff (O(D²) memory, capped) + diff3 grouping where touching changes from both sides conflict, like git; with repeated lines it may pick a different equally-minimal alignment than git.
- File paths from clients go through `cleanPath` (no traversal, no hidden/`.git` entries) and `regularFile` (Lstat, rejects symlinks).

### Frontend
- Hash routing in `App.svelte` (`#/`, `#/login`, `#/usuarios`, `#/p/<id>`); `Workspace.svelte` is lazy-loaded so CodeMirror stays out of the main bundle. Pages in `src/routes/`, shared code in `src/lib/`.
- `lib/editor/collab-client.js` — `CollabSession` owns one WebSocket + `EditorView` per open file: pushes `sendableUpdates` one batch at a time (`inflight` until `pushed`), applies `updates` with `receiveUpdates`, reconnects with backoff resuming from `getSyncedVersion`. Cursors are only sent when there are no pending local changes; received cursors are mapped through pending changes (`lib/editor/cursors.js`).
- `lib/editor/marginGuide.js` — JetBrains-style right-margin guide (purely visual vertical line at column N): a CodeMirror `layer` behind the text, x = real column-0 coordinate of a visible line + N × `defaultCharacterWidth`, omitted when it would fall past the visible width (lines wrap, and it would add horizontal scroll). Column per browser in `localStorage` `typsteditor.margin` (default 100, 0 = off), chosen in the toolbar «Más» menu (`onaction('margin', col)`) and applied live through `CollabSession.setMargin` (a `Compartment`).
- `lib/editor/typst-lang.js` — hand-written `StreamLanguage` highlighter (markup/code/math mode stack); no Lezer grammar.
- **Ortografía** (`lib/spell/`, `lib/editor/spellcheck.js`): español de México, todo en el navegador. `scripts/spell-dict.mjs` (plugin `spell-dict` de `vite.config.js`, se regenera si falta o cambia el paquete) expande con `nspell` el Hunspell de `dictionary-es-mx` (devDependencies) a ~550 000 formas en `src/lib/spell/es-MX.words.txt` (gitignored; codificación frontal: primer carácter = 48 + longitud del prefijo común, orden de `Array.sort`), importado con `?url` (asset con hash; `static.go` comprime `.txt`). `spell.worker.js` lo guarda como una sola cadena + `Int32Array` de inicios (búsqueda binaria por unidades UTF-16; ~15 MB) y sugiere: 1 edición con costes de confusiones del español, luego esa edición + hasta dos cambios «baratos» (acentos y letras que suenan igual), y 2 ediciones completas solo si no salió nada; `COMMON` prioriza palabras frecuentes (el diccionario no trae frecuencias). `speller.js` (singleton): caché palabra→correcta, diccionario personal (`localStorage` `typsteditor.spell.words`), ignoradas de la sesión, activación (`typsteditor.spell`). `spell/prose.js` `collectWords` decide qué es prosa con el árbol de `typst-lang.js` (texto sin nodo, o nodos `heading`/`strong`/`emphasis`/`strong_emphasis`/`list`); `spellcheck.js` revisa lo visible ± 3000 caracteres con debounce (y al avanzar el análisis), nunca la palabra que se escribe, y muestra el menú como tooltip de CodeMirror (`contextmenu`, tecla de menú, o un toque en móvil vía `pointerType`). `CollabSession` lo monta en un `Compartment` (`setSpell`; solo `.typ/.txt/.md` y no en solo lectura); interruptor en «Más» (`EditorToolbar` prop `spell`) y en el menú ⋮ del móvil. `typst-lang.js` trata como código el resto de la línea tras `#let/#set/#show/#import/#include` (y sus paréntesis) y sigue los bloques ```` ``` ```` de varias líneas (`rawBlock`).
- `lib/workspace/FileTree.svelte` — file explorer built from the flat `files` list (paths): collapsible folders (collapsed set persisted per project in `localStorage` `typsteditor.tree.<id>`, ancestors of `currentPath` auto-expand), accent/case-insensitive search over the full path (Enter opens the first match, Esc clears), icons by extension. Clicking an image opens `lib/workspace/ImageLightbox.svelte` (full-screen spotlight via `imageCache`: fit to window, wheel/double-click/+−0 zoom around the pointer, drag to pan, ←/→ across the project's images, «Insertar» when a `.typ` is open, open in tab / download); other non-editable files open in a new tab.
- **In-browser compilation** (`lib/preview/`): `typst.worker.js` runs typst.ts (`@myriaddreamin/typst-ts-web-compiler` + `-renderer`, **pinned to 0.8.0-rc4 = typst 0.15**; `WASM_TYPST` must match the server's typst minor version or the preview falls back to the server, since pagination must match the PDF). Fonts are lazy (`add_lazy_font` + sync XHR, FontInfo computed from the skeletons and cached in IndexedDB by catalog etag); project files come from the preview mirror via `map_shadow` (the open file via `add_source` with live editor text); packages through `set_package_registry` + an in-memory access model under `/@memory/packages`. Compiles with `incr_compile` (~0.25 s per edit on the 248-page thesis, ~6 s cold, ~1.5 GB worker memory) and keeps the first full artifact + deltas; warnings come from a cached `snapshot().compile(0, 3)` because `incr_compile` omits them. The renderer omits what a session already emitted (it is built to patch a DOM), so every render batch uses a fresh session (base + merged deltas), and `svgpage.js` cuts `render_in_window` output into standalone per-page SVGs (only the defs each page references, no `<foreignObject>` text layer). `engine.js` wraps the worker in promises.
- `lib/workspace/Preview.svelte` — compiles in the browser by default (`livePath`/`liveVersion`/`liveText` from the open `CollabSession`, `onDocChange`; `remoteKey` bumps on `rev` for other files → re-sync files); page keys are `<doc>:<index>` and a rendered page whose SVG signature didn't change keeps its blob URL. While the worker prepares, one server compile is shown, and the first browser compile waits for it (two >1 GB compiles at once would swap on a small box). Any worker failure → `fallback()` to the server path below. Server path, virtualized: reserves each page's box (aspect ratio from `/preview`), downloads pages near the viewport (IntersectionObserver, 4 in parallel, blob URLs keyed by hash, LRU of 24) and mounts an `<img>` only after the page stays close for 150 ms (each mounted SVG costs Chrome several MB until GC, so fast scrolling must not decode every page). Unchanged hashes are reused across recompiles; a changed page keeps showing the old version until the new one arrives. Clicking a page calls `onjump` (Workspace reuses `onDiagnostic`); clicking in the editor (`CollabSession` `onCursorClick`) calls the exported `reveal(file, line)`, which scrolls and briefly highlights the block. The sync map is fetched on first use and then refreshed 2.5 s after each compile. Zoom 40–400 % with Ctrl+wheel (non-passive listener added manually: Svelte's `onwheel` is passive), +/−/0 when focused, and the toolbar; `setZoom` keeps the page point under the pointer fixed. Left-drag pans (grab cursor); a drag sets `moved` so the following click doesn't jump to source. Compiles only while `active` (output panel visible), recompiling on `refreshKey` changes driven by WS `rev` messages with a debounce that grows with compile time. `PdfView.svelte` fetches the PDF blob into an iframe.

- **Tablas** (`lib/editor/tablecode.js`, `lib/workspace/TableModal.svelte`, `lib/editor/tableHover.js`): `tablecode.js` parses a `table(…)[…]` call (own Typst scanner: strings, `[…]` markup with escapes/raw/math/embedded `#…`, comments) into an R × C grid of anchor cells `{r, c, rs, cs, body, extra, lead}` placed like typst's auto-placement (header/body/footer start new rows), and `generate` writes one line per row in row-major order (empty positions as `[]`), which reproduces the same grid; cell bodies, other named args (`stroke`, `fill`…), per-cell args and comments are copied verbatim, `columns`/`align`/`rows` arrays stay in step with inserted/deleted tracks, flow `hline`s keep their row boundary. Refuses (message in the hover card) tables with `..spread`, explicit cell `x:`/`y:`, or a `columns:` whose count it can't know. Merging joins the non-empty contents (nothing is lost); merges can't cross the header/footer. `TableModal` is the graphical editor (size picker, rows/cols/header rows, insert/delete rows and columns, merge/split, column widths, own undo). - **Bibliografía** (`lib/bib/`): `bibtex.js` parses BibTeX/BibLaTeX keeping UTF-16 positions of type, key and every field value, and its edit helpers (`setField`, `removeField`, `setKey`, `setType`, `deleteEntry`, `appendEntry`) return **minimal changes** (only the touched value), so the rest of the file keeps its formatting and git diffs stay small; new fields go before trailing metadata (`META`: `creationdate`…). `BibEditor.svelte` is the visual mode of a `.bib` (Workspace toggle «Visual | Código», persisted in `localStorage` `typsteditor.bibmode`): it edits the **same** `CollabSession` document through `applyChanges` (`userEvent: 'input.visual'`, so remote users get normal OT updates and Ctrl+Z works), re-parses on every `liveVersion`, follows the selected entry with `session.track(entry.from)` (key as fallback) and never overwrites a field that is focused or has a pending debounced write.
